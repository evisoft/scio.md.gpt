# OpenAI plugin requirements audit — 2026-10-03

## Current-documentation refresh — 2026-10-09

The official [submission field reference](https://developers.openai.com/plugins/deploy/submission) now explicitly allows `review.test_cases`, `review.demo_recording_url` and `publication.release_notes` directly under `extensions.com.openai` in the ZIP. They are optional package fields, but initial MCP review still requires exactly five tested positive cases, three tested negative cases, a reviewer-accessible video and dedicated login credentials supplied privately in the dashboard. The current [plugin guidelines](https://developers.openai.com/plugins/plugin-guidelines) also say authenticated reviewers need an immediately usable account with sample data, no inaccessible MFA or magic-link step, and desktop/mobile reliability. The package's draft cases and missing video cannot satisfy that gate yet.

The current [authentication guide](https://developers.openai.com/plugins/build/auth) is more explicit than the older snapshot: tool-level linking needs both per-tool `securitySchemes` and runtime `_meta["mcp/www_authenticate"]`, in addition to protected-resource metadata. The current server source does not visibly add `securitySchemes` to listed tools; inspect the actual wire response and fix the platform if absent. The package's local checker now treats missing or incorrect schemes, schemas and side-effect hints as failures when an authenticated token is supplied. Its 2026-10-09 live attempt stopped at DNS before any HTTP exchange.

The four listing URLs and square SVG icon were accessible or shape-checked on 2026-10-09. This is local evidence only, not a portal validation or product-policy review. The [privacy notice](https://scio.md/privacy) currently describes Google sign-in and agents' public actions; the platform owner should confirm its OAuth/ChatGPT data-flow disclosure before submission. The [terms](https://scio.md/terms) and [support page](https://github.com/evisoft/scio.md/issues) were also reachable.

The current [remote MCP review requirements](https://developers.openai.com/plugins/deploy/app-review) add an operator prerequisite that the older checklist did not name: MCP plugins cannot currently be submitted from an OpenAI project with EU data residency. Use a global data residency project under the verified publisher identity, with `api.apps.write` for creating/submitting drafts and `api.apps.read` for viewing them. This concerns the OpenAI project selected in the portal; it does not require changing where Scio hosts its data. The page also says to omit screenshots when the plugin has no UI, as this package does.

The current [submission error reference](https://developers.openai.com/plugins/deploy/submission-errors) lists accepted categories explicitly. The package previously used `Research`, which is not accepted; it now uses `Education & Research`, and a regression test checks that value against the published list. The same reference still requires per-tool annotation justifications at final submission while the [guidelines](https://developers.openai.com/plugins/plugin-guidelines) say they are no longer required. Prepare concise explanations of the server's actual annotations for the portal finding; prose cannot override incorrect wire metadata.

The same error reference requires `interface.display_name` and `interface.short_description` whenever a packaged skill includes `agents/openai.yaml`. The first local archive had only the MCP dependency in that file, which would trigger `skill_agent_interface_missing` at import. The archive now declares both interface fields alongside the dependency; an automated test guards them. `SKILL.md` no longer carries ignored interface-like `metadata`.
